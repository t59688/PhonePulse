# 森林兔子生活重构设计

日期：2026-10-09。状态：用户已确认并要求开发；2026-10-09 补充授权无需保留旧陪伴数据。

## 目标与范围

用 `thridparty/04_taro_explorer.svg` 的兔子作为唯一主角，让用户放下手机之后，兔子在森林里生活、旅行、认识朋友，带回故事与礼物，共同从一片空地建起木屋。

成功标准：第一次进入能看懂“这是我们的家”；第一次有效休息能看到新的旅途内容与建家进度；多次旅行的收获不限于固定单件物品；已收到的明信片、风景和朋友有长期留存与再次出现的地方；装扮和建设直接改变场景。

本次重构范围是已有 companion 模块及其首页入口、归来反馈、分享。屏幕记录、电量统计、应用统计和原有导航继续按现有架构运行。

设计假设：保持本地离线；朋友为森林故事角色；旅行自动发生；不要求每次手动开始专注。实际可发行内容始终来自经过编写和校验的内容包，“任意东西”指收获模型与内容目录可扩展，而非承诺无限生成世界。

## 路线选择

1. 推荐：场景驱动的森林生活。家园是主屏，旅行见闻、建造、装扮围绕它发生。最符合正向鼓励离开手机的目的。
2. 收藏驱动：扩充图鉴和随机奖励，实施成本低，但仍容易成为固定清单与收集任务，无法支撑从零建家的体验。
3. 操作驱动：主动派遣、经营生产和大量建设队列，可玩性更强，但会增加查看手机与处理事务的负担。

采用路线 1。家园和旅行是两个相互支持的部分：离开手机产生见闻和建设进度，回到应用只需短暂看看、做一个选择。

## 核心体验

### 初次相遇

- 首屏是森林空地：树桩、简单铺盖、背包和兔子。没有预先建好的房屋。
- 默认展示原 SVG 的探险帽和斗篷；这套初始服装可以卸下、穿回，不需要抽取。
- 一句对白：“这里很适合安家。我去找点木头，你去忙你的吧。”
- 选择兔子名字可稍后进行，不阻挡进入。
- 初次休息后带回建家材料和一段见闻，保证有明确的第一次变化。

### 自动旅行与归来

- 继续从真实、已完成的熄屏区间结算，不要求手动开启计时。
- 亮屏只是结束这段可验证区间，不写成“旅行失败”。短于有效旅行门槛的记录不扣进度。
- 有效旅行沿用 10 分钟门槛；首版继续保留每日最多 5 次实体礼物结算，作为兼容起点。
- 每次有效旅行保证一段见闻；可额外包含礼物、明信片、风景记录、朋友事件。一次旅程允许多种收获共存。
- 达到实体礼物上限后仍可获得见闻和有上限的建设进度，不显示“奖励耗尽”。
- 更长的休息增加旅程长度与内容变化，收益在 3 小时后封顶；不设计要求通宵等待的专属奖励。
- 多段旅行通过同一个归来摘要呈现，点击后再逐段展开，不逐条连续弹窗。
- 在途状态只能根据实际记录状态展示；后台不可用时不伪造兔子持续出游。

### 内容世界

内容包由地点、季节/天气氛围、角色、事件、视觉资源、收获定义组成。氛围是故事设定，不宣称使用真实天气。

| 收获 | 示例 | 留存位置与用途 |
| --- | --- | --- |
| 物品 | 松果、蓝陶杯、旧地图、围巾 | 行囊；可收藏、穿戴或布置 |
| 明信片 | 湖畔寄来的手写小卡片 | 信箱；有正面画面和背面兔子留言，可分享 |
| 风景 | 雾中的石桥、傍晚的蘑菇林 | 旅册；可回看、装框挂到木屋墙面 |
| 趣闻 | 松鼠把一粒橡果误认成了行李 | 旅册；来自关联地点和角色的完整短故事 |
| 朋友 | 会修屋顶的啄木鸟、住溪边的水獭 | 朋友记录；记住初遇、重逢、来访和礼物 |
| 建材 | 木料、石材、纤维 | 建造库存；支持确定的建设进展 |

- 地点不再仅由时长映射成固定四处；结合旅程长度、已发现路线和近期重复情况选择。
- 同一朋友能连续出现：初遇、重逢、拜访；不用每次随机创建一个新名字。
- 新内容优先，但不要求全部内容都抽中过。重复物品进入库存，重复事件不会冒充新发现。
- 首版趣闻是原创森林故事；如果未来增加真实自然知识，内容需要来源与核验流程。
- 不显示“已收集 13/13”或满屏未解锁剪影；未知世界用地点与旅册逐步展开。
- 首发内容的最低验收数量：6 个地点、每地点至少 4 个事件、3 位有重逢与来访事件的朋友、12 张明信片/风景画面、12 件可装饰或穿戴物品；组合不能只是替换同一句话中的地名。

## 从空地到森林木屋

| 阶段 | 场景变化 | 新能力 |
| --- | --- | --- |
| 林间空地 | 铺盖、背包、树桩 | 收到第一段见闻，开始攒材料 |
| 小营地 | 简单遮雨棚、木箱、邮筒 | 信箱和户外摆放位置 |
| 木屋地基 | 地板与立柱逐步出现 | 选择门口位置和基本屋顶颜色 |
| 木屋落成 | 屋顶、门窗、室内地面 | 进入室内，布置家具、挂风景画 |
| 温暖的家 | 灯、床、桌、植物、小径 | 完善房间，接待朋友来访 |

- 每一步有明确材料需求与可见进度；基本建材使用确定结算，不靠稀有抽奖推进主线。
- 首次有效休息保证可建出小营地；木屋落成默认需要累计 180 分钟有效休息，分多次完成也计入。
- 建设增量按每次旅程封顶 180 分钟、每日封顶 240 分钟计算，向下一阶段结转；一次长休息不会自动跳过所有场景。
- 各阶段材料成本由同一配置定义，测试验证上述首营地和木屋节奏。木屋之后家具属于长期装饰，不设有限期完成任务。
- 建造前可预览，点击“搭起来”后消费材料并改变场景，无建造倒计时与到点领取。
- 累积进度不会因漏一天、频繁亮屏或停止使用而损失。
- 原成长值作为历史陪伴记录保存，家园进度采用新的明确建设模型，避免等级与房屋阶段含义混杂。

## 页面与视觉规格

### 家园

- 顶部仅返回、家园名称和分享；主视觉占首屏约 60%，采用有纵深的横向森林场景，兔子是其中的居民。
- 兔子在门口、树桩或屋内；在途时空地/木屋仍存在，留下背包位置与简短状态。
- 邮筒、木屋、兔子和朋友都是可点对象，同时提供等效的文字按钮，不能只靠找到画面热点操作。
- 下方一条最近来信/归来摘要、一个当前建设动作，不堆叠成长值、任务领奖与稀有度面板。
- 底部二级导航为“家园 / 旅册 / 行囊”；朋友记录放在旅册，信箱由场景和来信摘要进入。
- 建造与室内布置用详情页/底部面板打开；装扮在兔子入口打开。

### 旅册与信箱

- 旅册按旅行排列，画面与一段短故事优先，时长等统计放到详情。
- 一次旅行详情包含地点、见闻、带回的物品与遇到的朋友，不把内容拆成互不关联的奖励卡。
- 明信片正面展示风景，背面展示兔子留言、寄出地点与日期；已收到的信件离线可读。
- 风景进入个人收藏，朋友进入独立名册；可从名册看到该角色完整重逢记录。
- 首版信件随真实区间结算投递，回到应用就能看见；不额外引入后台定时寄送机制。

### 行囊、装扮与布置

- 行囊只展示已获得内容，按“衣物 / 家具 / 纪念物 / 建材”分类。
- 帽子、斗篷/衣服、围巾、随身物分别有明确槽位；默认帽与斗篷可独立卸下。
- 装扮先在兔子身上试穿，再保存；取消时恢复原装扮。
- 家具采用少量语义位置：门口、窗边、桌面、墙面、庭院；首版不用自由拖拽和复杂坐标编辑。
- 同一家具实例不能同时占两个位置；替换回收原物品；检查阶段是否支持该位置。
- 房屋颜色和已有物品的布置可预览与撤销，不产生消耗。

### 视觉与动作

- 严格沿用原兔子的长耳、一侧垂耳、奶油身体、棕色线条、探险帽、金黄斗篷。
- SVG 现有 `ears_back / body / feet / arms / head / face / clothes_cape / accessory_hat` 分组作为原始形体和装扮图层依据。帽子与斗篷不得烘焙进不可更换的身体贴图。
- 森林、木屋、朋友、家具统一采用圆润手绘矢量语言，不用表情符号替代主要美术。
- 日间为柔和苔绿与奶油纸张，夜间为深森林与暖窗灯；跟随本地时间呈现场景氛围，文字保证对比度。
- 首版使用可维护的 Android 矢量资源和共享静态合成渲染，保留原 SVG 源文件；不为单个角色引入生产依赖。
- 仅归来、建成、换装发生短暂动作；静置无持续帧循环，无后台动画。
- 分享复用相同兔子图层与家园状态，可分享当前家园或收到的单张明信片。

## 状态、错误与正向鼓励

- 载入中使用稳定的场景占位，禁止显示假库存或假建成状态。
- 尚无旅程：“下次回来，听我讲路上的事。”保留可看的空地与初始装扮。
- 未开启记录时显示简短状态与“开启记录”，不构造假旅程。
- 保存失败保留已持久化状态，显示重试；不能视觉成功后丢失材料。
- 中途亮屏、没有稀有礼物、暂时没有旅行均无扣分、愧疚对白或破坏家园。
- 夜间睡眠不要求手动领取成长；取消每日领奖任务作为主要激励，已有任务历史保留。
- 不增加催促查看的推送、签到、连胜、排行榜、饥饿值和错过惩罚。
- 故事、物品、建设均可晚些查看，朋友没有必须定时喂食的状态。
- 产品界面保留名称、状态、对白和动作；规则、概率与实现细节留在文档中。

## 实现边界与数据契约

- 保留 `CompanionRepository + CompanionStore` 边界及 Mutex/原子保存策略。
- 扩展 Journey 的多收获列表，使用带类型的内容引用。旧 `itemId` 迁移为物品收获，原始旅程时间和 ID 保持不变。
- 将可发行内容定义与用户已获得的实例分离：稳定 definitionId、独立 instanceId、sourceJourneyId、receivedAt 和必要的故事快照。
- 已收到的明信片正文与风景引用需持久化；内容包更新后不得重新随机生成旧来信。
- 使用有限的收获类型与独立处理器/渲染器扩展内容；常规增加物品、地点或故事只增加目录定义，不改结算核心。
- 增加 HomeState（阶段、材料、已建设部件、家具位置、外观）、FriendState（发现、互动事件、来访历史）、Mailbox（信件和阅读状态）。
- 用户补充：本版本未上线，不迁移旧陪伴状态；使用 forest_rabbit_v2 独立存储，从空地重新开始，原屏幕和电量记录保留。
- 本版本用户均从空地开始，并拥有原 SVG 的探险帽与麦芽斗篷。
- 现有 60 条旅行裁剪策略不能继续删除已收藏信件、风景和朋友；收藏存独立集合，普通旅行历史可分页/按现有策略保留摘要。
- 重复奖励以区间 ID 和稳定实例 ID 去重；归来摘要的阅读状态与收藏状态分开。
- 原子事务保存结算游标、旅行、所有收获、材料和建造状态；失败可安全重试。
- 不添加新的服务、轮询、WakeLock、账号或网络生成接口。

## 实施顺序与验收

1. 数据模型、内容包契约和独立 v2 存储。
2. 旅行结算：多种收获、非重复选择、故事快照、朋友连续性、确定建材和建设节奏。
3. SVG 分层资源和家园场景：五阶段、日夜、装扮、家具位置、室内。
4. 家园、旅册、行囊、明信片与归来摘要，以及原首页入口和分享更新。
5. 回归验证和模拟器检查。

必须验证：跨午夜连续区间合并与结算去重；旧陪伴存储不被读取、原屏幕记录不重置；同旅程多收获保存；每日上限与短区间无惩罚；基础建设不会卡在随机奖励；建造材料不足与重复点击；朋友初遇/重逢；试穿取消；收藏跨历史裁剪保留；分享画面一致；更新弹窗与归来面板互斥；保存失败后无重复发奖。

使用项目命令 `gradlew.bat testDebugUnitTest`、`gradlew.bat assembleDebug`、`gradlew.bat lintDebug`。模拟器检查空地至木屋、小字体/大字体、日夜、信件、换装与分享，并确认静置无持续重绘。文档阶段不宣称这些实现检查已通过。
