# 电池数据真实性修复

适用范围：PhonePulse 当前电池采集、持久化、容量健康、预测、提醒和用户更新后的电池 UI。保留现有架构和四个子页，不引入生产依赖。

## 数据口径

| 数据 | 来源及限制 |
| --- | --- |
| 电量、温度、电压、插电状态 | Android 实际报告；缺失显示未知，非法电量不写历史。系统电量本身也是设备燃料计的估计，应用无法保证它等于物理剩余电荷。 |
| 电流、charge counter | BatteryManager 实际读数，可手动校准方向、单位和电芯口径；不自动猜测机型容量或双电芯。 |
| 净电荷 mAh | 由有效电流区间积分，或可信计数器差值得到。延迟计数器更新与已积分电荷对账，避免重复累计。没有覆盖的时段不填待机电流。 |
| 亮屏、熄屏电荷 | 按区间起点屏幕状态归属，并独立记录实测时长；无覆盖不显示 0 mAh。熄屏不等于深睡，时钟挂起时长不是硬件睡眠状态检测。 |
| 容量与健康度 | 合格充电会话的净电荷 / SOC 变化外推，取最近五个合格容量的均值；健康度还需要手动设计容量。属于估算，不能用一致性指标证明绝对准确度。 |
| 剩余时间 | 近期实际 SOC 速度或已测电荷速度推算；充电优先同电源类型的 SOC 分段历史，再回退合格当前会话速度。暂停充电、数据过期、缺少依据时不显示倒计时。 |
| 应用使用时长 | UsageStats 系统记录。前台时长占比不能作为应用耗电比例，因此不再展示按时长分摊的耗电百分比或 mAh。 |
| 今日电量下降 | 相邻有效 SOC 采样观察到的下降百分点之和，不是完整全天能耗或库仑计量。较长缺口及未知插电状态不用于屏幕放电速率归因。 |
| 图表 | 电量图为实际采样点连线，中间并非连续测量；容量图按合格记录顺序排列。 |

## 保留的常量

这些是配置和证据门槛，不是伪造的测量数据：提醒默认目标 80%（用户可修改）、采样和持久化节奏、120 秒实时数据有效期、容量估算的最小 SOC 跨度及覆盖率、最近五个容量样本、30 天预测历史、365 天会话保存、异常值及预测上限。

FULL 状态配合绝对电流不超过 100 mA、连续有效观测五分钟，是软件的满电确认规则，不是对电气终止、危险过充或寿命损失的测量。高电量时长按观测 SOC ≥80% 统计。移除了固定浮充时间、寿命倍数和“电压曲线积分”等缺少实现依据的说法。

## 兼容与回归

Room 升级至 v4：电池记录的温度、电压改为可空，新增可空插电状态；会话新增各屏幕状态实测时长。显式迁移保留既有记录和 ID。旧记录无法分辨 25°C、4000 mV 是真实测量还是旧默认值，不猜测重写；无法证明的旧分桶覆盖显示未知。

回归覆盖延迟/量化计数器、双通道切换、挂起覆盖、恢复及电源边界、未知传感器、未知插电状态、过期数据、首次 100% 无测量、暂停充电、局部 SOC 预测、应用能耗口径、数据库迁移和 UI 缺失态。

真机传感器准确度、不同 OEM / 双电芯读数口径、长期容量误差及与 AccuBattery 的对照仍需真实设备与外部电量基准验证。模拟器与单元测试不能证明精度超过 AccuBattery。
