# 电池分析与养护实施设计

依据：`accubattery-2.1.8-analysis.md`；用户已要求按审查结论完整实施。

目标：在既有电量页和前台服务中交付实时电流、可靠净电荷计量、可恢复充放电会话、估算容量保持率、趋势和排除管理、充电目标提醒、情境剩余时间预测及测量校准设置。沿用 Compose / Flow / Room，不新增生产依赖。

架构：单一服务采样队列 → 纯 Kotlin BatteryAnalytics → Room 会话/checkpoint 与分钟汇总 → BatteryMonitorRepository 的 Flow → MainViewModel → 现有页面。Android 传感器和提醒实现分别封装。UI 与广播不能启动第二套积分器。

正确性：原始读数不可用保持 null；电流保留净流入/流出的符号；CPU 挂起与长缺口不使用瞬时电流补算；经过验证的 charge counter 只覆盖一次；状态边界归属旧桶；校准调整隔离会话；重启关闭不完整周期；短进程恢复计入缺口；提醒持久化去重与静音；数据不足不伪造健康/预测。100% 后计量与容量估算明确区分。容量使用充分覆盖、SOC 增幅 ≥60 点的周期；用户可排除异常会话，显示样本数和离散程度。

UI：沿用深色卡片、现有色彩/间距/字体。电池页新增实时监测、容量健康与趋势、养护设置、最近周期。系统枚举改为系统电池状态。设置提供设计容量、符号反转、倍率和双电芯口径、目标提醒与目标电量；说明调整影响。通知区给出监测状态/采样错误，目标提醒独立频道并有静音动作。

数据：Room v3 添加 battery_cycles / battery_intervals / battery_monitor_state；显式保留 v1→v2→v3 历史。分钟汇总保留 30 天，周期保留最近 365 天（可用于趋势），清理不移除活跃周期；UI 限量查询。采样每 5 秒（充电/亮屏）或 30 秒（息屏 CPU 醒着），不持有 WakeLock、不用精确闹钟。

计划与验收：

- [x] Room 迁移与 Repository；迁移历史保留、会话原子保存、校准/排除持久化、有限保留。
- [x] 服务采样、读数适配和提醒；串行采样、启停、异常恢复、提醒去重/静音/重启。
- [x] 电池页完整接入；未知值、校准输入验证、健康趋势、会话详情、操作错误呈现。
- [x] 修正既有耗电率分母与无数据表达，保留已有测试约定。
- [x] 全部相关单测、完整测试、lint、debug 构建、独立代码审查，修复发现问题。

实施结果和实机验证边界见 `battery-feature-delivery.md`。

真机边界：OEM 传感器口径、休眠广播延迟、实际采样耗电需要实机验证；交付报告明确记录，不宣称软件可硬件停充、测得每次寿命损失或精确 UID 耗电。
